# Design System: Screenly

## Overview

REQ-038 makes the user's supplied charcoal/Citron screenshot the visual authority. Keep this
compact dark workspace and refine its details. The rejected ultraviolet/lime direction and
large display typography are historical, not guidance. All shipped routes start dark before
hydration, regardless of saved Light/System preferences or operating-system appearance.
The light palette and selector component remain in source behind a disabled availability flag.

## Colors

Citron marks primary actions, links and keyboard focus. Selected roles use an olive surface
with Citron text and an explicit check. Black navigation, charcoal content, a slightly lighter
session panel and neutral rules establish depth. Use semantic success, warning and error pairs.
The unprefixed light values in frontmatter are retained internal CSS tokens; dark-prefixed
values override them in the shipped app. Component references below describe the shipped dark state.
Always pair backgrounds with their foreground tokens. Carets use link color and scrollbars use
input color so they remain visible. Preserve every light token without exposing a theme picker.

## Typography

The shared system-first sans stack is backed by local Geist Sans. Headings use the same family:
page title 26px/600, section title 16px/600, selected role 20px/600, UI 14px, labels 13px/500,
captions 12px. Avoid oversized or decorative type. Geist Mono serves code. The live stage keeps
its existing Overused Grotesk caption family and fitting; it is a preservation exception.

## Layout

Use the existing 240px navigation, 8px workspace inset, 52px header, 32px desktop content padding
and 1080px content maximum. New interview has a 1000px maximum, flexible role list, 340px brief
and 40px gap. At narrower desktop widths the brief is 300px and the gap is 24px. Role rows are
64px with 4px between them. The brief has 24px padding, 20px groups and an 88px goal editor;
narrow/short windows use 20px padding and an 80px goal editor. Keep submit beside its settings.
No new composition, content or navigation model is authorized by a polish request.
The existing below-1024px guidance preserves mounted sessions and drafts; landing remains responsive.

## Elevation & Depth

Use neutral surface differences and rules for ordinary grouping. Menus and dialogs use the
existing soft, offset shadows. Keep the setup brief flat and avoid new decorative depth.

## Shapes

Controls use 8px corners, role rows and setup panel 12px, and larger existing frames/dialogs
16px. Preserve native textarea resizing and existing dock geometry. No colored planes, glows
or decorative borders replace the supplied reference.

## Components

Buttons retain their label while busy, disable duplicate activation and share owned hover,
active, disabled and focus states. The ordinary desktop minimum is 40px, with 44px coarse-pointer
targets. Inputs retain visible boundaries and clear focus. Role selection remains six native
keyboard-operable radio choices. The header, skeleton and recovery layouts match their destination.
Keep capability failures, missing experience, explicit goal-save note and create errors inline.
Settings exposes audio playback and account information; the Appearance component remains in
source but is not rendered. Never let stored preference or system changes expose light mode.
The core orb, captions, timer, dock, transcript and audio/session ownership remain preserved.

## Do's and Don'ts

- Do use the supplied screenshot for palette, type, proportions and density.
- Do polish alignment, text/control contrast, focus, hover, loading and short-window fitting.
- Do retain real data, all recovery actions and existing product behavior.
- Don't expose Light, Dark or System controls to users while appearance selection is disabled.
- Don't restore the rejected purple panels, neon fill selections or alternate display fonts.
- Don't alter the live stage or introduce new flows during this polish pass.
