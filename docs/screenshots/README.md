# UI captures

These images are browser screenshots of the rebuilt Screenly application, generated by `CAPTURE_SCREENSHOTS=1 bun run test:e2e`. They use local controlled LLM and Deepgram protocol fixtures with simulated microphone input. Text, scores, account names, and timings are test data. They demonstrate presentation and behavior, not live-provider quality.

Desktop routes cover landing, authentication, overview, setup, preflight, live interview, feedback, and history. Additional captures cover the active interview at 1440 and 1536px, history at 640px, and setup, navigation, live voice, and feedback at 360px. No screenshot or generated raster is used as a runtime frontend asset.

Refinement captures include `preflight-mobile.png` and `interview-transcript-1440.png` / `interview-transcript-360.png`, showing the open preflight surface and optional inline read-back at desktop/mobile sizes.

`caption-highlight-desktop.png` and `caption-highlight-mobile.png` show the full generated question with a visual speaking highlight. These captures use the same controlled providers and simulated input described above. The highlight is a presentation effect and never controls or segments audio.

Sidebar captures: `sidebar-expanded.png`, `sidebar-collapsed.png`, `sidebar-search.png`, `sidebar-mobile.png`, and `sidebar-interview-focus.png`. These show the supplied-reference navigation refinement, remembered icon rail, command search, compact mobile drawer, and temporary interview focus using the controlled browser-test account.

`sidebar-search.png` and `sidebar-search-mobile.png` show the compact command-search refinement with plain destination rows and no title block or footer. The updated expanded sidebar capture omits the removed session callout. These use the controlled sidebar browser journey described above.

The refreshed shell captures use the 56px workspace header and 64px rail. `sidebar-collapsed-settings.png` additionally shows Settings selected in the actual local development preview, with the account avatar unobstructed by development controls. The remaining refreshed captures use the controlled browser journeys above.

`preflight.png` and `preflight-mobile.png` show the minimal session-summary/audio-controls layout. `preflight-checking.png` shows the real input meter during the four-second check; `preflight-resume.png` shows the saved-session action and remaining original budget. `preflight-recovery.png` shows a denied microphone with its retry action in the audio-control column. These use the controlled microphone/provider browser journey above.

The refreshed `interview-voice-1440.png`, `interview-voice-mobile.png`, and transcript captures show Transcript in the interview content toolbar, below the app bar, beside the larger elapsed timer. The mobile toolbar stacks its session details above the timer and transcript action.

`auth.png` shows the Google-only production sign-in page. `auth-local.png` shows the same page on a development server with the explicitly enabled local email entry. These screenshots were captured from the running application after fonts, session checks, and control transitions settled; the fern voice visual is static, and no microphone is active.

`onboarding-import-desktop.png`, `onboarding-import-mobile.png`, `onboarding-focus-mobile.png`, `onboarding-review-desktop.png`, and `onboarding-settings-desktop.png` show the six-step profile flow, compact mobile forms, explicit AI review/approval, and saved background/projects in Settings. `onboarding-projects-desktop.png` shows repeatable projects; `onboarding-compact-desktop.png` shows the complete focus form at 1280×720 without page or form scrolling. Long reviews and small screens scroll only the working panel, with actions pinned.

Generate them with `CAPTURE_ONBOARDING=1 bun run test:e2e --grep 'detailed manual|real compressed PDF'`, then copy the matching `onboarding-v2-*` captures from `apps/web/.impeccable/review/`. These use synthetic candidate details, real generated document extraction, and controlled model responses. Captures wait for local fonts and settled controls. They demonstrate app behavior, not live profile/provider quality, and are documentation assets only.
